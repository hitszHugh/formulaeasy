# 产品笔记：用户、需求与差异化

这份文档记录产品判断，不记录实现细节。实现变更看提交历史。

## 一句话定位

给中文理工科用户的本地公式工作台：截图进，**能编译的 LaTeX** 或**能粘进 Word 的公式**出；
模型自己选，数据不出机器。

## 谁会真的部署它

按"必须本地"的强度排序，不是按人数。

| 类型 | 为什么必须本地 | 他们最在意什么 |
| --- | --- | --- |
| 涉密/内网单位（试卷、专利、未发表论文、医疗、法务） | 内容不允许上传公网 | 合规、可审计 |
| 实验室/课题组 | 一台内网机器多人共用 | 装一次大家都能用 |
| 教师/培训机构 | 题库批量数字化 | Word 格式、批量、速度 |
| 出版/编辑 | 扫描稿转排版 | 长文档、结构、可校对 |
| 个体研究生/极客 | 有自己的 API key，嫌订阅贵 | 便宜、能改、不依赖服务 |
| 二次开发者 | 想要一个可改的底座 | 代码可读、Prompt 可换 |

大众学生用户不是本地版的目标：Mathpix、SimpleTex、各类扫描 App 更省事。
本地版的价值不在"离线"，在**可控、可改、可集成**。

## 用户真正要办的事（按痛感排序）

1. 少打字：截图到公式，从 30 秒变成 5 秒。
2. 能直接用：粘进 Word 就是公式对象，粘进 `.tex` 就能编译。
3. 别丢结构：多行推导、分组、编号（①②③）、条件与标注。
4. 别让我校对到崩溃：不确定的地方要标出来，而不是装作全对。
5. 批量：一页纸、一整本书，而不是一张图。
6. 别上传：数据留在本机。
7. 按我的模板来：学校/期刊的导言区、编号、中文格式。

## 差异化：强、中、弱

**强（工程正确性，别人不做）**

1. **编译可验证**：输出附带 `packages` 与 `notes`，能用声明的宏包编译通过；
   缺包、`&` 位置、环境未定义这些问题在源头被拦掉。多数工具只给一段字符串。
2. **结构保真**：保留行序、分组、推导步骤与中文标注，而不是识别成一坨。
3. **本地 + 自带模型 + 零构建**：一个 node 进程，没有 Docker、没有 Python 环境；
   OpenAI 兼容接口，DeepSeek/豆包/Qwen/内网模型随意换。
4. **可改**：单文件服务端 + 原生前端，改 Prompt、加后处理、接自家模板都是几行的事。

**中（是承诺，还不是优势）**

5. Word 线性格式：已改写为 UnicodeMath，单行公式粘进 Word 能成型；多行只能拆成
   多条独立公式，不做方程组排版。定位是辅助出口，不是主路径。
6. 长图与分段：滚动已支持，分段识别尚未做。

**弱（不要当卖点）**

7. 免费：不是护城河。
8. 识别准确率：通用视觉模型打不过专用公式模型。
9. 网站停服时可以自给自足：真实但低频。

## 不该做的事

- 不做通用 OCR（表格、整页手写、版面还原），打不过专用方案。
- 不做云端 SaaS，与"数据不出机器"的定位冲突。
- 不做编辑器，Word 和 Overleaf 已经够好。
- 不靠"更准"竞争，靠"更可用、更可控"竞争。

## 路线（按价值排序）

已放弃"出卷/Word 深度排版"这条线：题号、分值、答案、图形、模板每一样都是独立工程，
会长成一个排版系统。产品收缩为"公式工具"——图片进，可编辑的 LaTeX 与图片出。

1. **渲染与图片输出**（已完成）：MathJax 渲染、编辑即时预览、复制 PNG。
2. **输出三选一**（已完成）：LaTeX / 图片 / Word（单行）。
3. **评测层**：真实图片跑场景验收，改 Prompt 前后可对比。
4. **批量**：多图排队识别。
5. **本地模型落地**：把 `OCR_PROVIDER=local` 从占位变成真离线。

## 已定决策

- 工作副本放在 `fork`，后续计划自建仓库，不再向原仓库提 PR。
- 验收按**用户场景**组织，不按函数组织：单公式、多行推导、分段函数、矩阵、中英混排。
- 硬不变量是"能编译"：用模型声明的 `packages` 拼最小文档跑 xelatex，零 `!` 错误。
- 不替用户决定导言区：带圈序号缺字这类问题写进文档，不在运行时硬塞 preamble。
- 不在运行时猜测用户环境；能证明的才自动修（`&` 的位置、`\&` 的转义）。
- 整齐优先于逐字还原：参差的 `aligned` 会被改写成共享左边界。
- Word 只保留单行能力，多行不做方程组排版（`eqArr` 需要生成 docx，已放弃）。
